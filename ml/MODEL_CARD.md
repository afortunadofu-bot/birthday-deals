# Model card：投稿欄位自動預填

一句話：拿已經人工標好的生日優惠，訓練三個文字分類器，讓投稿審核的時候可以先填好
「優惠型態／入會方式／類別」三欄，沒把握的留白給人填。

產出頁面：<https://afortunadofu-bot.github.io/birthday-deals/ml-autofill.html>

## 要解決的問題

壽星日的優惠有一部分是使用者投稿的。送進來是一段自由文字（品牌、優惠內容、條件），
但資料庫裡那三個欄位是編碼過的選項，現在靠人一筆一筆判斷。
這個模型的工作不是取代判斷，是**把有把握的那些先填好**。

## 輸入與輸出

| | 內容 |
|---|---|
| 輸入 | 品牌名 ＋ 優惠內容 ＋ 條件（投稿表單上一開始就會打的三格） |
| 輸出 | `free_tier` 4 類、`membership_type` 6 類、`category` 9 類，各自附一個信心值 |

**刻意不用的欄位**：`membership`（「麥當勞 APP 會員」這種自由文字）。
它幾乎等於把 `membership_type` 的答案寫在臉上，而且是同一個人在同一個畫面填的——
模型要在那之前給建議才有用。把它加進特徵，入會方式的準確率會從 55.6% 跳到 68.7%，
那 13 個百分點是假的。

## 資料

- 來源：壽星日線上資料庫的公開 view `offers_public`，581 筆已核可優惠（2026-11-24 抓）
- 標註：全部是我自己整理資料時標的，沒有另外請人標，也沒有第二個人複核
- 類別很不平均：最大的類別佔 49%（優惠型態）／30%（入會方式）／40%（類別）
- `free_tier` 標成 `unknown` 的 6 筆不收（那是「還沒標」，不是一個類別）
- `membership_type` 的 `card`（9 筆）與 `tier`（4 筆）合併成「其他」，
  否則五折交叉驗證分不出來

## 方法

- 特徵：字元 n-gram TF-IDF（`char_wb`、2–4 gram、`min_df=2`、sublinear tf）。
  不斷詞——中文斷詞器對「大麥克或勁辣雞腿堡＋小薯$89」這種混了品名、數字、
  符號的短句常切壞，而且會多一個依賴
- 模型：比了 ComplementNB、羅吉斯迴歸（平衡／不平衡）、校準過的線性 SVM，
  三個任務都是**羅吉斯迴歸（class_weight="balanced"）**的 macro-F1 最高
- 驗證：五折 StratifiedKFold，用 out-of-fold 預測算所有指標，random_state 固定
- 一定有 baseline：「永遠猜最大宗類別」

## 結果（五折交叉驗證）

| 任務 | baseline | 準確率 | macro-F1 | 上線門檻 | 自動填覆蓋率 | 自動填的準確率 |
|---|---|---|---|---|---|---|
| 優惠型態 | 49.0% | **81.7%** | 74.8 | 0.6 | 64.0% | 92.4% |
| 入會方式 | 30.3% | 55.6% | 39.5 | 0.8 | 10.5% | 93.4% |
| 類別 | 40.1% | 57.8% | 45.0 | 0.6 | 13.8% | 91.2% |

門檻是這樣挑的：在「自動填的那些至少九成正確」的前提下，取覆蓋率最高的那個點。
九成是自己定的——預填錯一欄的代價是審稿的人改回來，不是災難。

## 已知的弱點

- **入會方式這個任務不該這樣做。** 優惠文字裡通常根本沒寫怎麼入會，
  模型只能猜。覆蓋率 10.5% 等於九成的投稿還是得人填。
  真正的解法是從品牌官網或同集團既有品牌去推，不是硬套文字分類器。
- **類別的瓶頸是分類法，不是模型。** 把餐廳／火鍋／燒肉／速食合併成「餐飲」
  再分一次，準確率從 57.8% 跳到 69.5%。這四類在語意上互相包含
  （燒肉店也是餐廳），人在標的時候也會猶豫。
- **「免費無低消」最弱**（recall 28.6%）：它跟「免費有低消」的差別常常藏在
  條件欄的一句話裡，有時候根本沒寫。
- **581 筆是小資料。** 每一折的驗證集只有 116 筆，少數類別只有幾筆，
  指標本身就有不小的波動。這裡只跑了一個 random_state，沒有做重複交叉驗證。
- **標註者只有我一個人。** 沒有標註一致性可以算，模型學到的是我的判斷習慣，
  包含我的不一致。

## 不該拿它做什麼

- 不要直接寫進資料庫。它是預填，送出前要有人看過
- 不要拿去判斷別的網站的優惠文字。訓練資料全部是壽星日自己的寫法
- 不要用它的信心值對外宣稱什麼。那是模型對自己的信心，不是事實的機率

## 怎麼重跑

```bash
cd ../analysis && python fetch_live.py && python build_db.py --live
cd ../ml && pip install -r requirements.txt && python train.py
python predict.py "品牌 優惠內容 條件"
```

模型檔（`models/*.joblib`，約 1.8 MB）不進版控，`train.py` 20 秒內可以重建。
