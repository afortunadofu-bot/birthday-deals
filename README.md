# 壽星日 — 台灣生日優惠整理站

民眾可自由新增優惠、管理員審核核可、使用者回報最新使用日期與留言。
部署在 https://birthdaydeals.celine-fu-work.workers.dev/。

> **先跑起來看看**：直接雙擊 `index.html`。沒設定 Supabase 時會進入
> **離線示範模式**，用內建的種子資料，可以完整體驗瀏覽與篩選。
> 要開啟登入／投稿／留言，照 **[SETUP.md](SETUP.md)** 走一次（全部免費，約 30 分鐘）。

> **完整版本紀錄**在 **[CHANGELOG.md](CHANGELOG.md)**——每次資料庫變更都有
> 對應的 `schema_vN_*.sql`，新版本上線前記得先貼進 Supabase SQL Editor 跑
> 一次。以下這份 README 只留 v1–v3 那次大改版的說明，之後的每個版本都在
> CHANGELOG 裡。

## v3 新增

### 1. 會員種類拆開列出

不再只是一句「需加入會員」，而是分成七類，可以直接篩選：

| 種類 | 筆數 | 說明 |
|---|---|---|
| 免加入會員 | 21 | 出示證件就有 |
| 品牌 APP | 12 | 要下載該品牌 APP |
| 品牌會員（管道未明） | 11 | 確定要入會，但管道待查 |
| Ocard（跨品牌） | 8 | **辦一次通吃多家**，CP 值最高 |
| LINE 官方帳號 | 4 | 加 LINE 好友即可 |
| 實體／數位會員卡 | 1 | 如 IKEA Family |
| 需達會員等級 | 1 | 如星巴克綠星級 |

另外標了**入會成本**：多數是免費註冊，但好丘、小時厚牛排需要有消費紀錄，
星巴克需要先累積到綠星級——這些卡片上會直接寫「（需有消費紀錄）」「（需達等級）」。

### 2. 完全免費的單獨列出

依你說的分兩層，用不同顏色區分：

| 層級 | 筆數 | 意義 |
|---|---|---|
| 💚 **免費・無低消** | 7 | 不用花任何錢。卡片加綠色外框 |
| **免費・需消費** | 25 | 東西免費，但要先點餐或達低消 |
| 折扣／買一送一 | 26 | 有折扣但仍要付錢 |

**免費・無低消的 7 筆**：鮮茶道（送紅茶）、31冰淇淋（免費單球）、好丘（貝果或司康）、
Popeyes（比司吉）、六福村（指定月份免費入園）、自己做（4 吋蛋糕）、吳家紅茶冰（$30 折抵，
最低價飲品等於免費）。

### 3. 民眾投稿 + 管理員審核

- **新增優惠**分頁有完整表單，欄位跟資料庫一致（會員種類、免費層級、縣市、提前天數、檔期、來源）
- 送出後狀態是 `pending`，**不會馬上公開**
- 管理員在**審核後台**看到待審佇列，可以「核可」或「退回」，
  核可時可勾選「同時標記已查證」（代表你真的去官方確認過）
- 退回時寫的備註，投稿者在「我的紀錄」看得到
- **投稿者不能自己把狀態改成已核可**——這是在資料庫層擋的，改前端沒用

### 4. 使用回報與留言

- 卡片上有「我用過了」按鈕：填**使用日期**、結果（成功／部分成功／失敗）、門市、備註
- 卡片會顯示「✅ 最近有人用：3 天前（2026-08-01）　成功率 85%　12 次回報」
- 超過 120 天沒人回報會轉成橘色提醒，代表資料可能過時
- 排序可選「依最新回報」，把還活著的優惠排前面
- 篩選有「只看近 90 天有人回報」
- 展開「留言與回報」可看完整歷史紀錄與留言串

這是整套設計裡最有價值的一塊：**懶人包會過期，但使用者的回報不會**。
一筆優惠即使原始資料是半年前的部落格，只要上週有人回報成功，可信度就完全不同。

## 資料來源可信度（v2 沿用）

| tier | 分級 |
|---|---|
| 1 | 品牌官方 |
| 2 | 新聞媒體 |
| 3 | 部落格懶人包 |
| 4 | 社群貼文 |

同一筆有多個來源時顯示等級最高的。目前分布：官方 1、媒體 3、部落格 54。
**這仍是最大的資料弱點**，逐步補官網連結是投報率最高的改善。

---

## 縣市與期限（v2 沿用）

- 全台連鎖 36 筆、區域限定 19 筆、地區未確認 3 筆
- 選「台中市」顯示 50 筆（台中限定 + 全台連鎖）；地區未確認的會被隱藏
- 常態優惠 vs 限期檔期分開顯示，剩 14 天內轉紅色，過期預設隱藏

## 爬蟲（v2 沿用）

```bash
python scraper.py            # 部落格/新聞
python threads_client.py --dry-run   # Threads，不用 token 先驗證解析
```

**Threads 的三個關卡**（詳見 `threads_client.py` 檔頭）：
需 App Review 通過 `threads_keyword_search` 權限（否則只搜得到自己的貼文）、
每日 2,200 次查詢上限、圖片裡的文字需另接 OCR。

兩支爬蟲都**只產出待審報告，不自動上線**。

## 安全性

前端的 anon key 是公開的，所有防護靠資料庫 RLS。完整對照表在 [SETUP.md](SETUP.md) 末段。
重點：**沒有人能把自己變成管理員**（trigger 擋）、投稿一律強制 `pending`、
每人每日投稿 10 筆／留言 30 則上限、同一天同一筆優惠只能回報一次。

## 已知限制

- 一人可辦多個 Google 帳號洗回報，目前只能靠人工觀察
- 管理員權限要用 SQL 指令給，沒有後台介面
- 沒有留言檢舉機制（資料表已預留 `is_hidden` 欄位）
- Supabase 免費專案連續 7 天無活動會被暫停，可一鍵恢復
